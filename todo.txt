[x] introduce file level tag set setting or something like that, i.e. we set tag "x" and "z::y" with line "#tags: x z::y" and until another #tags:
    comes along we will be loading words with associating them with the tags "x" and "z::y".
    Syntactic elements
        %    ... comment, will be totally ignored, this is what # was till now.
        #    ... set   tag level-1, reset tag levels above, tag list required
        ##   ... set   tag level-2, reset tag levels above, tag list required
        ###  ... set   tag level-3, reset tag levels above, tag list required
        #-   ... reset tag level-1, reset tag levels above, tag list dissallowed
        ##-  ... reset tag level-2, reset tag levels above, tag list dissallowed
        ###- ... reset tag level-3, reset tag levels above, tag list dissallowed
    Example:
        # A::B C D::E::F
        eesnimi
        % eesnimi will have the tags: A::B C D::E::F
        % Thus with only # you can do everything, and the additional tag levels are only for convenience and probably an overkill feature.
    Example:
        #  A B
        ## C D
        eesnimi
        % now eesnimi will have tags: A::C A::D B::C B::D
    Thus the way this is evaluated is that for each tag in level x it appends tag from tag level x+1
    Thus if you don't want complex multiple times occuring tags under another tags then don't use this and only write for example
        #  A
        ## C D
        eesnimi
        % then you will only have eesnimi with tags: A::C A::D
        % Or just write as what the first example suggested:
        # A::C A::D
    Example:
        #  A::C
        ## B
        eesnimi
        % now there is only a single tag: A::C::B
    The point of this
        is to write a file, be able to set the root or 2 which will be used for all but set level-2 tags for sub-sets of the file.
        Example usage would be the Tere book, there I want to be able to have the tags source::Tere::chapt_05 for example.
        That at the moment with the file name based solution (i.e. that you define a list of tags by the separator being "__") is not possible
        because its not possible probably to have colons in file names.
    The problem I now realized
        is that I am not handling very smartly another requirement that I have, which is to set some tags which shall be added to all but
        which shall not be considered during the chaining process.
        Example:
            @ source::Tere::bluebox
            # source::Tere
            ## chapt_05
            eesnimi
            ## chapt_06
            perekonnanimi
        Where
            eesnimi       tags: source::Tere::bluebox source::Tere::chapt_05
            perekonnanimi tags: source::Tere::bluebox source::Tere::chapt_06
        NOTE
            although until now implicit - when you set a particular tag level the previous tags of that level are overwritten with the new ones.
